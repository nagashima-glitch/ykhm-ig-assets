# AI 発注ルール（どれに何を頼むか）

目的: 同じ仕事を高いところに投げてトークンを溶かさない。
考え方は「**考える場所**」「**作る場所**」「**任せる場所**」を分けるだけ。

---

## 1. 3 層に分ける

| 層 | 使うもの | 役割 | コスト |
|---|---|---|---|
| L0 壁打ち・企画 | ChatGPT 無料 web / Claude web チャット | やりたいことを言語化する。リポジトリは見せない | ほぼ無料 |
| L1 単純作業 | Codex（軽いプロファイル） | 仕様が決まっている機械的な作業 | 安い |
| L2 判断が要る作業 | Claude Code（Opus）/ Codex deep（Astra high） | 仕様が曖昧・複数ファイル・設計・GitHub 運用 | 高い |

**鉄則: L0 で「発注書」を作ってから L1/L2 に渡す。**
曖昧なまま L2 に投げると、探索（ファイルを読み回る）でトークンの大半が消える。

---

## 2. タスク別ルーティング表

| タスク | 投げ先 | 理由 |
|---|---|---|
| IG 投稿の企画・文案・構成 | **ChatGPT 無料 web**（または Claude web） | コードもリポジトリも不要。無料枠で十分 |
| IG 画像/リールの追加・レビューページ生成 | **Claude Code（web）** | 既存フローが動いている。1 投稿 = 1 セッション |
| HP の新規ページ・構成変更・改築 | **Codex deep** または **Claude Code Opus** | 設計判断が要る。ここは高推論を惜しまない |
| HP の文言・色・画像差し替え | **Codex fast** | 場所が特定済みなら軽いモデルで足りる |
| 一括リネーム・定型置換・フォーマット | **Codex fast** | 完全に機械的 |
| 原因不明のバグ・表示崩れ調査 | **高推論（Astra high / Opus）** | 安いモデルで何往復もする方が高くつく |
| GitHub の PR・CI 対応・レビュー返信 | **Claude Code** | GitHub 連携が標準で入っている |
| サイネージ（ykhm-signage）の更新 | 内容次第で上の行に従う | リポジトリでは分けない |

---

## 3. トークンを減らす実務ルール 5 つ

1. **1 タスク 1 セッション。** 会話が長いほど毎ターン過去分を読み直す。終わったら新規セッション。
2. **探索させない。** 「どこかにあるはず」ではなく `posts/2026-09-13/index.html` のようにパスで渡す。
3. **壁打ちは無料枠で。** 「どう作るか」を決める往復は L0 でやる。有料エージェントには決まったものだけ渡す。
4. **発注書テンプレ（§4）で渡す。** 完了条件が書いてあると一発で終わる。
5. **大きい資産を読ませない。** `posts/` は 40MB 超。画像そのものを解析させる用事がなければ触らせない。

---

## 4. 発注書テンプレ（L0 で作るもの）

```
【目的】何のためか（1 行）
【対象】リポジトリ / ファイルパス
【やること】箇条書き。各項目に「できたと分かる条件」
【やらないこと】触ってほしくない範囲
【確認方法】どう見れば成功か（URL / コマンド / 見た目）
```

これをコピペして投げれば、L1 でも L2 でも同じ品質で通る。

## 5. Codex 側で「重い作業は賢いモデル」を自動化する

**前提（正直なところ）: Codex はタスクの中身を見て自動でモデルを切り替える機能を持たない。**
できるのは次の 3 段構えで「ほぼ自動」にすること。

### (a) プロファイルを用意する
`~/.codex/config.toml` に `docs/codex-config.example.toml` の内容を追記。
以後 `codex --profile deep` / `codex --profile fast` で切り替わる。

### (b) ディレクトリで自動的にプロファイルを選ぶ
シェル関数を `~/.zshrc`（bash なら `~/.bashrc`）に置く。
HP のリポジトリに居るときは自動で deep、資産リポジトリでは fast になる。

```sh
codex() {
  local profile=fast
  case "$PWD" in
    *ykhm-hp*|*homepage*|*site*) profile=deep ;;   # HP 改築は常に高推論
    *ykhm-ig-assets*|*signage*)  profile=fast ;;
  esac
  command codex --profile "$profile" "$@"
}
```
（明示的に `codex --profile deep` と打てばそちらが優先される）

### (c) セッション中の自己エスカレーション規約
各リポジトリの `AGENTS.md` に「重い作業だと分かったら推論を上げる」と書いておく。
Codex は着手前に AGENTS.md を読むので、実質的にエージェント自身が判断して上げてくれる。
手動なら対話中に `/model`・`/reasoning` で変更、単発なら `-c model_reasoning_effort="high"`。

---

## 6. 「Astra に発注」はアリか

アリ。ただし用途を分ける。

- **GPT-6 Astra（Codex の高推論）** … 設計・改築・原因不明のバグ。ChatGPT Plus の Codex から使える。
- **Claude Code（Opus）** … GitHub 運用（PR / CI / レビュー返信）と、この IG フローのような既に自動化済みの作業。
- **両方に同じ仕事をさせない。** 迷ったら片方に発注書を渡し、出てきた差分をもう片方にレビューさせる方が安い。

> モデル名と価格は変わる。`codex` 内で `/model` を叩いて実在する名前に置き換えてから使うこと。
